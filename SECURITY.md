# Security Policy

## Supported versions

agent waker has not had a release yet. Once `0.1.0` ships, only the latest
published version will receive security fixes until `1.0.0`.

Report issues against `main` in the meantime; the process below applies now.

## Reporting a vulnerability

**Please do not open a public issue for security problems.**

Report privately through GitHub's
[private vulnerability reporting](https://github.com/andreacappadona17/agent-waker/security/advisories/new).
This is a small project maintained in spare time: expect a first response
within about a week, and a fix as soon as one can be made.

Please include the affected version, reproduction steps, and the impact you
believe the issue has.

## Scope

agent waker runs third-party coding-agent CLIs on a schedule and persists
scheduling state on the local machine. Findings in these areas are especially
valuable:

- **Credential exposure** — agent waker must never read, log, persist, or
  transmit provider credentials. Any path that writes a secret to state, logs,
  or diagnostic output is a vulnerability.
- **Command injection** — subprocesses are spawned directly with argv arrays
  and no shell. Any path that builds a shell string from configuration or
  provider output is a vulnerability.
- **Untrusted provider output** — output from an agent CLI is data, never code.
  Report anything that evaluates it or lets it escape terminal rendering.
- **Privilege and isolation** — activation runs in a neutral working directory
  with closed stdin and an enforced timeout. Report escapes from that sandbox.
- **Generated scheduler and workflow files** — `launchd` plists and GitHub
  workflow files generated by agent waker must not grant more privilege than
  documented.

### Out of scope

- Vulnerabilities in Claude Code, Codex, or other agent CLIs. Report those to
  their vendors.
- Provider rate-limit behaviour. agent waker deliberately does not bypass
  provider policy.
- Anything requiring an attacker who already has local code execution as the
  user running agent waker.

## Our commitments

- agent waker never instructs users to disable operating-system security
  controls, and never installs, modifies, or repairs third-party agent CLIs.
- Secret scanning, dependency auditing and static analysis run in CI on every
  change; security tooling and GitHub Actions are pinned by digest and commit
  SHA; dependencies are quarantined for a release-age cooldown before they can
  be installed. The mechanisms are documented in
  [CONTRIBUTING.md](CONTRIBUTING.md#dependency-policy).
